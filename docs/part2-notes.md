# Part 2 notes — Motif surfaces

Running list of moments worth writing up for the part-2 case study (MCP server, FigJam plugin). One dated line per moment. Numbers and quotes are copied from the file named in the line, never recalled.

- 2026-09-04 — Started the MCP-server build chat from `docs/specs/motif-mcp-server.md`. Step zero (verify Figma's MCP write path to FigJam on a real board) was put before any Motif code, on the reasoning that if a host can already write to FigJam through Figma's own MCP server, the MCP surface can ship before the FigJam plugin instead of depending on it.
- 2026-09-04 — Spec discrepancy: the spec's "Tools to expose" list has four tools (synthesize, critique, receipts, runs.get); the brief for this chat says five. Fifth is unconfirmed; proposed candidate is a board-output tool that depends on step zero. Source: `docs/specs/motif-mcp-server.md`.
- 2026-09-04 — Figma's write path exists and covers FigJam: the `use_figma` tool executes Plugin API JavaScript against the open file, with a `figma-use-figjam` skill for boards (stickies, sections, connectors, text, shapes, tables, code blocks). Writing requires the *remote* server (`https://mcp.figma.com/mcp`) and OAuth; the desktop server is read-only. Sources: developers.figma.com tools-and-prompts page; github.com/figma/mcp-server-guide skills `figma-use` and `figma-use-figjam`; help.figma.com guide (writes "currently available for free during the beta period", will become "usage-based paid").
- 2026-09-04 — Gotchas recorded from the `figma-use-figjam` skill: no `figma.createPage()` in FigJam (throws); `get_metadata` fails on FigJam files, use `get_figjam`; `console.log` is not returned, only `return` values; fonts must be loaded before any text mutation; every write script must return the created node IDs. `use_figma` targets the file whose `fileKey` is passed, and the file must be open.
- 2026-09-04 — Machine state at step zero: Figma desktop 126.8.16 running (from `pgrep -lf figma`); local MCP port 3845 refused (`curl` exit 000); remote endpoint answers 401 with `www-authenticate: Bearer ... authorization_uri="https://api.figma.com/.well-known/oauth-authorization-server"` and also lists `X-Figma-Token` as an allowed header — a personal access token may be an alternative to OAuth, untested. No Figma token on the machine (`.env` has only `ANTHROPIC_API_KEY`).
- 2026-09-04 — Registered the Figma remote MCP server in Claude Code local scope for this project (`claude mcp add --transport http figma https://mcp.figma.com/mcp`); status "Needs authentication". Step zero is blocked on the OAuth click, which only the account owner can do. Verification on a real board not yet run.
- 2026-09-04 — Engine read for the architecture: 1,337 lines across `core/` and `synth/` (from `wc -l`). Surprise: `synth/cli.py` shells out to `scripts/ingest.py` and `python -m synth.run` as subprocesses and finds the run directory by parsing stdout for `-> ... output.md`. The loop wiring lives inside `synth/run.py::main`, so there is no importable "engine service" yet — extracting one is the first build step, and it is the same service the FigJam plugin needs.
- 2026-09-04 — Hazard found: `core/logger.py::RunLogger` and `synth/run.py` print progress to stdout. An MCP server on stdio transport uses stdout for the protocol, so any print corrupts the stream. The logger needs an emit hook (stderr by default; MCP notifications in the server) before the server can exist.
- 2026-09-04 — Design gap in the spec: `motif.receipts(turn_ids)` has no corpus argument, but a turn id like `michelle:0042` only means something against a corpus. Proposed fix: runs snapshot their processed corpus into `runs/<id>/corpus/`, and receipts/critique take a `run_id`. The CLI currently ingests to a `mkdtemp` folder under `/tmp` that a run never records (`synth/cli.py`).
- 2026-09-04 — Tool naming: spec names use dots (`motif.runs.get`). Some MCP hosts restrict tool names to `[A-Za-z0-9_-]`; plan is to expose underscore names (`motif_runs_get`) and keep the dotted names in docs as logical names.
- 2026-09-04 — Step zero PASSED. After OAuth, created a throwaway FigJam board via Figma's `create_new_file` (`https://www.figma.com/board/GQRzxmNRE8MlIhEqh5UwXe`, on the pro-tier team; the starter team was skipped because it caps file counts). One `use_figma` call with skills `figma-use,figma-use-figjam` created a section, three stickies (claim / receipt / counter-evidence, colour-coded yellow / green / red) and a labelled connector, and returned node ids `1:2, 1:7, 1:11, 1:15, 1:19`. `get_figjam` read all five back inside the section; screenshot matches. Evidence: `docs/exhibits/step-zero/board.png`, `docs/exhibits/step-zero/readback.xml`.
- 2026-09-04 — Consequence: the MCP surface no longer depends on the FigJam plugin for board output. The host (Claude Code, Cursor) can write a Motif run onto a board through Figma's own MCP server; Motif only has to hand it a layout. Motif never needs Figma credentials.
- 2026-09-04 — Surprise: the sticky palette doc lists red as `#FFB8A8`, but the readback reports that sticky's colour as `CUSTOM` while yellow `#FFE299` and green `#B3EFBD` came back as palette colours (`docs/exhibits/step-zero/readback.xml`). The board tool should pin its palette to colours that round-trip, or accept custom fills.
- 2026-09-04 — Decisions from the user: the spec has five tools — synthesize, critique, receipts, board, runs_get — board being the fifth and dependent on step zero. Architecture approved: engine module, logger emit hook, corpus snapshot per run.
